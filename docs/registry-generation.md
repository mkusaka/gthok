# Registry generation

Generate Git grammar at development time from Git source, not from help text.
The runtime embeds JSON and needs neither that source tree nor a C compiler.
Pin **Git v2.56.0**, commit `a018953688f1b10bddf91bff8747068f5f4746a4`.

## Regenerate

Use a local checkout of exactly the pinned commit and the local Git v2.56.0
binary. No generation step fetches or queries a remote.

```sh
GIT_SRC="$HOME/src/github.com/git/git"
go run ./internal/registry/gen -git-src "$GIT_SRC" -out internal/registry/data -verify
go test ./internal/registry/gen ./internal/registry ./internal/normalize/git
```

`make registry GIT_SRC="$GIT_SRC"` generates the same syntax data but omits
completion verification; use the explicit **-verify** command above before
checking in artifacts, since the regeneration test compares the verified
manifest byte-for-byte. The test skips its source-dependent comparison only
when the pinned source or matching local Git is unavailable.

Outputs are `internal/registry/data/commands.json`, `grammar.json`,
`source-map.json`, `manifest.json`. Commands include builtins, scripts,
standalone tools, early root modes and documentation-only subjects; the latter
are not executable commands. The manifest records source pin, generator version,
coverage/exclusions and optional validation evidence.

## Extraction and manual adapters

Primary evidence is source: git.c command/root parsing, option constructors and
struct option tables, subcommands, callback arity, flag groups, revision/diff
options and implementation entrypoints. Completion/help are validation only;
they never decide an unknown option is a no-value switch.

Unknown option constructors, parse flags and low-level callbacks fail generation
rather than silently inventing arity. Shared/conditional tables carry adapter
reasons. Hand-parsed commands need explicit audited adapters. For example,
fetch-pack's reversed strcmp spellings and attached values come from its C
entrypoint; bisect start/terms and run-child forwarding are manual grammars.
Reflog safe display options reuse log/revision declarations; unsafe unmodeled
side-effect flags, line-range logging and custom formats (which may verify
signatures) remain unknown until the semantic adapter is updated.

Some runtime semantic adapters also supply source-reviewed grammar details
(e.g. submodule shell dispatch, update-index callbacks and object plumbing).
Changing extraction is not enough: add a focused parse/semantic test and check
unknown/retrySafe behavior for newly accepted flags. Do not introduce a parsed
read whose output/filter/editor side effects are ignored.

## Action catalogue and schemas

`internal/normalize/actions` is the registered family/action/effect catalogue;
`internal/normalize/git.ActionRoutes()` supplies examples for every registered
action. `gthok actions [glob] --json` renders it with example scopes. The full
reference is in [normalization](normalization.md); conditional mode changes still
require normalizing the actual invocation.

Generate all Draft 2020-12 contracts from tagged Go types:

```sh
go generate ./internal/schema
go test ./internal/schema
```

Checked-in `schema/*.schema.json` must equal generated bytes. Config field tags
and the Go contracts are the source of truth, not hand-edited JSON. CLI envelope
mirrors in internal/schema must stay aligned when the CLI output changes.
Doctor preserves its existing uppercase JSON keys. Version prints text by
default; `gthok version --json` emits the version schema's release metadata.

Final checks: `gofmt -l .`, `go build ./...`, `go vet ./...`, `go test ./...`,
`make lint`. All real-Git tests use isolated local temporary repositories and
must not touch the network.
